摘  要
随着人工智能与物联网技术的深度融合，智慧家居正从室内单场景向庭院等开放式生活空间延伸。本文提出并实现了一种基于 ESP32-S3 微控制器的智慧庭院生态平台，创新性地采用“主机负责智能交互，从机负责实时执行”的主从协同架构。系统深度集成大语言模型驱动的语音交互、多模态传感器融合感知、基于 MCP（Model Context Protocol）的自然语言意图落地以及 MQTT 轻量级协议统一总线，支持自然语言控制庭院设备、成语意境场景智能切换、多传感器联动自动控制以及火灾安全本地闭环响应等核心能力。测试结果表明，该平台具备低延迟、高可靠性与良好的可扩展性，为大模型时代智慧庭院的实际应用提供了一种具有前瞻性的技术方案。
关键词：
智慧庭院；AIoT；ESP32-S3；MQTT；大语言模型；MCP；语音交互；主从协同架构
目  录
第一章  绪论
1.1  研究背景
当前，以大语言模型（LLM）为核心的人工智能技术正在重塑万物互联的交互范式，而物联网（IoT）技术的迅猛发展则为智能设备的普适化铺平了道路。两者的深度融合——即 AIoT（Artificial Intelligence of Things）——正在开启智慧生活的全新篇章。然而，现有智能家居解决方案大多聚焦于室内场景，对于庭院、花园等室外开放空间的智能化管理仍然是一片待开发的蓝海。
庭院作为住宅与自然的过渡空间，承载着休闲娱乐、生态景观、安防监控等多重功能。传统庭院管理主要依赖人工操作，存在三大痛点：其一，灯光、浇灌、通风等设备需要人工逐一控制，操作繁琐且效率低下；其二，缺乏环境感知能力，无法根据天气、土壤湿度等条件自动调节设备状态；其三，安全防护能力不足，火灾等异常情况难以及时发现和处理。这些问题严重制约了庭院生活品质的提升，也与当下智慧化、自动化的时代趋势相悖。
1.2  国内外研究现状
在智能家居领域，国内外已涌现出诸多成熟解决方案。国外以 Amazon Alexa、Google Home、Apple HomeKit 为代表的智能语音助手平台，通过云端 AI 提供语音交互能力，已形成较为完善的生态体系。国内则有小米、华为等厂商推出的全屋智能方案，在设备互联与场景联动方面积累了丰富经验。然而，这些方案大多针对室内场景设计，对庭院等室外场景的覆盖有限，且多依赖封闭生态，可定制性与可扩展性不足。
在庭院自动化领域，现有研究主要集中在智能浇灌系统和环境监测系统两个方面。智能浇灌系统通过土壤湿度传感器控制水泵，实现自动化浇灌；环境监测系统则通过温湿度、光照等传感器采集环境数据。但这些系统往往功能单一、彼此孤立，缺乏从感知到决策再到执行的全链路智能化设计，更未能融入大语言模型等新一代 AI 能力，难以满足用户对“说即达意”的智慧庭院期待。
1.3  本文工作
针对上述痛点与研究空白，本文提出并实现了一种基于 ESP32-S3 微控制器的智慧庭院生态平台，具有以下创新特色：
● 
主从协同架构：主机专注于大模型语音交互与 AI 推理，从机专注于传感器感知与执行器控制，实现智能与实控的优雅分离。
● 
大模型驱动的自然语言控制：集成小智语音协议与 MCP 工具链，用户可通过自然语言无缝控制庭院设备，支持成语意境场景的智能切换。
● 
多模态传感融合感知：集成土壤湿度、雨滴、火焰、温湿度等多类型传感器，实现跨模态数据融合与联动控制。
● 
安全事件本地闭环：火灾检测采用本地 ADC 阈值轮询，不依赖云端与网络，确保极端情况下的安全性。
● 
MQTT 统一总线：采用 MQTT 协议作为主机、从机、App 端的统一通信基础设施，实现多端协同互联。
第二章  系统总体架构设计
2.1  系统架构概述
本系统创新性地采用“智能主机 + 执行从机”的协同架构，将 AI 推理与物理控制解耦部署。主机基于 ESP32-S3 搭载小智语音协议，负责语音唤醒、ASR 识别、LLM 推理、TTS 合成、MCP 工具调用以及 MQTT IoT 控制器功能；从机同样基于 ESP32-S3，专注于 GPIO/继电器/舆机/WS2812B 的实时刷新、ADC 与多种传感器的数据采集，以及本地安全联动逻辑。两者通过 Wi-Fi + MQTT 实现无缝通信，共同构成了一个完整的“感知—决策—执行”闭环。
2.2  设计原则
系统设计遵循以下核心原则，确保架构的清晰性、可靠性与可扩展性：
● 
关注点分离：主机不直接连接庭院负载，庭院执行器全部连接从机。主机专注于智能交互与决策，从机专注于实时控制与数据采集，职责清晰、各司其职。
● 
场景与自动模式正交：意境场景管灯光氛围，自动模式管设备控制，两者互不干扰。唯一例外是安全警戒场景会强制关断危险设备，体现安全优先的设计理念。
● 
安全事件本地闭环：火灾等安全事件首先在从机本地闭环处理，不依赖云端和主机，确保在网络异常时仍能保证安全。
● 
MQTT 统一总线：MQTT 是主机、从机、App 端的统一协议总线，所有设备通过 Topic 进行消息路由，实现松耦合、高可靠的多端通信。
2.3  技术栈
系统采用以下经过充分验证的技术栈，确保平台的稳定性与先进性：
● 
硬件平台：ESP32-S3 微控制器，支持 Wi-Fi、蓝牙、I2S、RMT 等丰富外设，为 AIoT 场景提供强大的计算与连接能力
● 
开发框架：ESP-IDF v5.5.3，Espressif 官方物联网开发框架，提供完善的驱动与工具链支持
● 
实时操作系统：FreeRTOS，提供任务调度、信号量、事件组等机制，保障系统实时性
● 
通信协议：MQTT v3.1.1，轻量级物联网消息传输协议，支持发布/订阅模式与断线重连
● 
语音交互：小智语音协议，支持唤醒词检测、ASR、TTS、LLM 全链路语音智能
● 
工具协议：MCP（Model Context Protocol），AI 模型与外部工具的标准化接口，实现意图到动作的精准映射

3.3  硬件安全设计
硬件安全设计是智慧庭院平台的重要基石，本系统从以下三个维度进行了深入考量：
● 
安防总闸：采用高电平导通设计，上电默认 GPIO17=1，只有火灾确认或明确切断时 GPIO17=0。这种“安全导通”的设计理念确保了异常情况下的自动断电保护。
● 
WS2812B 灯带：使用 5V 独立供电、共地、数据线串 330Ω~470Ω 电阻、入口并 1000µF 电容，长灯带使用 74AHCT125 电平转换，充分保障信号完整性。
● 
火灾传感器：采用 ADC 电压阈值轮询替代传统中断模式，从根本上杜绝继电器 EMI 干扰导致的误报，大幅提升火灾检测的可靠性。
第四章  软件架构与分层设计
4.1  软件分层架构
系统软件采用经典的三层架构设计，从底层到顶层依次为 BSP 层、APP 层和 Application 层，各层职责明确、接口清晰，实现了高内聚、低耦合的软件架构。BSP 层负责硬件抽象，屏蔽底层硬件差异；APP 层负责业务逻辑，实现核心功能组装；Application 层负责任务调度与状态管理，驱动整个系统的运转。这种分层设计使得各层可以独立迭代、互不影响，显著提升了开发效率与系统可维护性。
4.2  BSP 层设计
BSP（Board Support Package）层是软件架构的基石，负责硬件抽象，提供统一的硬件操作接口，使上层代码与具体硬件实现解耦。主要包括：
● 
bsp_wifi：WiFi 初始化与连接管理，封装 ESP-IDF 的 WiFi 驱动，提供阻塞式连接接口，确保网络连接的稳定性
● 
bsp_camera：摄像头初始化与传感器配置，封装 esp_camera 库，提供统一的图像采集接口
● 
bsp_mpu6050：MPU6050 六轴传感器驱动，支持硬件 I2C 和软件 I2C 两种模式，灵活适配不同硬件布局
● 
bsp_buzzer：蜂鸣器控制，提供开关和蜂鸣接口，用于安全告警与状态提示
● 
bsp_iot_controller：IoT 控制器底层，管理远程设备表、处理响应解析和状态缓存，是多设备协同的核心支撑
BSP 层采用函数指针的方式实现硬件抽象，例如 buzzer_t 结构体包含 Gpio_Init、Gpio_Write、Delay_ms 等函数指针，使得上层代码与具体硬件实现完全解耦，便于硬件平台的迁移与替换。
4.3  APP 层设计
APP 层是业务逻辑的核心载体，将 BSP 层的硬件能力组装为可复用的业务模块，向上层提供高级业务接口。主要包括：
● 
app_garden：智慧庭院核心业务模块，提供设备控制、场景切换、自动模式管理等接口，是平台业务逻辑的中枢
● 
iot_controller：MQTT 控制器，负责 MQTT 连接管理、消息收发、设备发现和心跳维护，是多端通信的桥梁
● 
app_fall_detect：跌倒检测模块，基于 MPU6050 加速度数据进行跌倒判断，提升庭院安全防护能力
● 
app_video_server：视频服务器，提供 HTTP MJPEG 流和 YOLO 推理框架，支持视觉 AI 能力的扩展
● 
app_mpu6050：MPU6050 应用层封装，提供初始化和数据读取接口，简化上层调用
4.4  Application 层设计
Application 层是系统的最高层，采用事件驱动的状态机架构，统筹调度整个系统的运行。主要特点包括：
● 
事件驱动：使用 FreeRTOS 事件组实现事件通知，包括网络连接、唤醒词检测、VAD 变化、状态切换等事件，实现模块间的松耦合通信
● 
状态机：定义了设备状态枚举（Idle、Connecting、Listening、Speaking、Activating 等），通过 DeviceStateMachine 管理状态转换，确保系统行为的确定性
● 
任务调度：Schedule 方法允许其他任务将回调函数投递到主任务执行，确保线程安全，避免竞态条件引发的数据竞争
● 
协议抽象：Protocol 接口支持 MQTT 和 WebSocket 两种协议实现，通过 OTA 配置动态选择，实现通信方式的灵活切换
4.5  MCP 工具层设计
MCP（Model Context Protocol）工具层是大语言模型与物理世界的桥梁，负责将自然语言意图精准映射到设备控制动作。McpServer 采用单例模式管理所有注册工具，每个工具包含名称、描述、参数列表和处理函数。当小智云端发送 MCP 请求时，McpServer 解析参数并调用对应的处理函数，返回 JSON 格式的执行结果。这种设计使得新增设备只需注册新的 MCP 工具即可接入系统，具备极强的可扩展性。

5.3  命令码体系
系统定义了完整的二进制命令码体系，分为三个类别，兼顾功能完备性与传输紧凑性：
基础命令（0x01-0x08）：
IOT_CMD_SET_GPIO (0x01)、IOT_CMD_GET_GPIO (0x02)、IOT_CMD_HEARTBEAT (0x04)、IOT_CMD_RESPONSE (0x05)、IOT_CMD_DISCOVER (0x06)、IOT_CMD_ANNOUNCE_V2 (0x08)，覆盖设备发现、状态查询与心跳维护等基础功能。
设备控制（0x10-0x13）：
IOT_CMD_SET_SERVO (0x10)、IOT_CMD_SET_LIGHT (0x11)、IOT_CMD_SET_RELAY (0x12)、IOT_CMD_SENSOR_REPORT (0x13)，实现舆机、灯光、继电器的精细化控制与传感器数据上报。
广播与场景（0x30-0x3B）：
IOT_CMD_BROADCAST_ALL_OFF (0x30)、IOT_CMD_EMERGENCY (0x34)、IOT_CMD_SET_AUTO_MODE (0x35)、IOT_CMD_SET_STRIP_RGB (0x39)、IOT_CMD_SET_AMBIENCE_SCENE (0x3A)，支持全局广播、紧急联动、自动模式与意境场景切换。
5.4  数据包结构
系统定义了紧凑的二进制数据包结构，仅 8 字节，专为低带宽 IoT 场景优化：
typedef struct { uint8_t command; uint8_t device_id; uint8_t gpio_index; uint8_t value; uint8_t reserved[4]; } __attribute__((packed)) iot_command_packet_t;
其中 reserved 字段用于扩展参数，例如设置灯带 RGB 时，reserved[0-2] 分别存储 R、G、B 值，reserved[3] 存储效果参数。这种紧凑而可扩展的设计，在保证传输效率的同时预留了充分的功能扩展空间。
5.5  设备发现与心跳机制
设备发现采用广播机制：从机上线后发送 IOT_CMD_ANNOUNCE_V2 命令到广播 Topic，携带设备名称和 GPIO 数量。主机收到后解析 MAC 地址，将设备动态添加到远程设备表，实现即插即用的设备接入体验。
心跳机制用于维护设备在线状态：从机每 10 秒发送一次心跳包，主机收到后更新设备的 last_heartbeat_ms 时间戳。主机每 10 秒检查一次设备超时，超过 60 秒未收到心跳的设备标记为离线。这种双向心跳机制有效保障了系统对设备状态的实时感知能力。
第六章  智慧庭院业务功能
6.1  设备控制
系统支持对庭院设备的精细化控制，实现了“语音即指令，设备即响应”的流畅体验：
灯光控制：
包括西庭灯（小黄色 LED）、庭院灯带（WS2812B RGB 灯带）和长廊灯（暖黄色 LED 灯带）。每路灯光可独立开关，灯带支持 RGB 颜色、亮度和效果（常亮、呼吸、彩虹、警示闪烁）的精确控制，满足不同场景下的氛围营造需求。
继电器控制：
包括通风扇、水泵、雾化器和安防总闸四路继电器。继电器采用高电平导通设计，安防总闸具有特殊的安全语义：高电平导通表示正常供电，低电平切断表示火灾熔断。
舆机控制：
智能遮雨棚采用舆机控制，支持 0°（收回）和 90°（展开）两个位置。舆机通过 LEDC PWM 驱动，精度为 1°，确保遮雨棚动作的平稳与可靠。

6.4  传感器联动
系统实现了多种传感器联动控制，构建了“感知—决策—执行”的智能闭环：
● 
土壤湿度→水泵：土壤湿度低于 45% 时自动启动水泵，达到 60% 时停止，实现精准灌溉。
● 
温湿度→风扇/雾化器：温度超过 32°C 或湿度超过 80% 时启动风扇，空气湿度低于 35% 时启动雾化器，智能调节庭院微气候。
● 
雨滴→遮雨棚：雨滴百分比超过 60% 时自动展开遮雨棚到 90°，同时切换灯带到烟雨漦胧场景；雨停后自动收回遮雨棚并恢复风和日丽场景，实现天气感知的无缝自动化。
6.5  火灾安全闭环
火灾检测采用 ADC 电压阈值轮询机制，实现了从感知到响应的全自动安全闭环，具体流程如下：
● 
从机每 500ms 采样一次火焰传感器 ADC 值，电压下降表示火焰靠近，百分比上升
● 
fire_percent &gt; 60% 连续 3 次（1.5 秒）判定为火灾确认，触发安全响应
● 
安全响应：安防总闸切断（GPIO17=0）、水泵/雾化器关闭、三路照明打开、灯带红色警示闪烁
● 
通过 MQTT 发布紧急事件，主机收到后进行 TTS 播报和蜂鸣器报警，实现多端协同告警
火灾自动解除：火焰移开后，电压回升，fire_percent &lt;= 60% 持续 15 秒，自动恢复安防总闸导通和正常灯效。这种“检测—确认—响应—解除”的完整闭环，体现了系统在安全场景下的自治能力。
第七章  AI 语音交互与 MCP 工具集成
7.1  小智语音协议接入
系统通过小智语音协议实现 AI 语音交互，构建了从唤醒到执行的全链路语音智能：
● 
唤醒词检测：音频服务持续监听麦克风数据，当检测到唤醒词时触发唤醒事件，开启语音交互流程
● 
ASR 语音识别：唤醒后，系统将麦克风音频数据通过 MQTT 发送到小智云端进行语音识别，将自然语言转化为文本指令
● 
LLM 推理：小智云端对识别文本进行大语言模型推理，生成回复文本和 MCP 工具调用指令，实现“说即达意”的智能体验
● 
TTS 语音合成：回复文本通过 TTS 合成语音，通过 MQTT 返回设备进行播放，完成自然对话体验
系统支持三种监听模式：AutoStop（自动停止）、ManualStop（手动停止）和 Realtime（实时），根据 AEC 配置自动选择，灵活适配不同交互场景。
7.2  MCP Server 架构
MCP（Model Context Protocol）Server 是大语言模型与物理世界的标准化桥梁。系统中的 McpServer 采用单例模式，提供以下核心能力：
● 
工具注册：通过 AddTool 方法注册工具，每个工具包含名称、描述、参数列表和处理函数，实现插件化的功能扩展
● 
参数解析：支持字符串、整数、布尔值等参数类型，提供 PropertyList 进行参数验证，确保调用安全性
● 
结果返回：处理函数返回 cJSON 对象，McpServer 自动序列化为 JSON 字符串发送到云端，实现结构化的结果反馈

9.3  总结与展望
本文提出并实现了一种基于 ESP32-S3 的智慧庭院生态平台，创新性地采用主从协同架构、MQTT 统一总线与 MCP 工具集成，实现了大模型驱动的语音控制、自动模式、成语意境场景切换和火灾安全闭环等核心功能。系统具有以下突出特点：
● 
架构优雅：主从分离设计，主机负责智能交互，从机负责实时执行，职责清晰、解耦彻底
● 
通信统一：MQTT 作为统一通信总线，支持主机、从机、App 端的多端互联，松耦合、高可靠
● 
控制灵活：支持语音控制、JSON 命令和二进制命令多种控制方式，覆盖不同交互场景
● 
安全可靠：火灾检测采用本地 ADC 轮询，不依赖网络，确保极端情况下的安全性
● 
扩展性强：MCP 工具架构支持灵活扩展，新增设备只需注册新的工具即可接入系统
