## 摘要

"银龄智享"是一款专为老年群体打造的"零屏幕、零门槛"边缘AI可穿戴终端，旨在让不会使用智能手机的老年人也能轻松享受AI科技带来的便利生活。本项目以ESP32-S3-N8R16为核心算力节点，创新性地将MCP（Model Context Protocol）工具协议与ESP-NOW分布式通信技术深度融合，构建了"AI大模型 + 语音交互 + 分布式物联网节点"的端云协同架构。

系统采用"一主机多从机"的分布式架构，主机以ESP32-S3为核心，集成小智AI语音助手与大模型推理能力，负责语音唤醒、意图识别和指令分发；从机设备分布在房屋各楼层，独立控制灯光、风扇、窗帘、药盒等终端设备。主机与从机之间通过ESP-NOW协议实现低延迟、低功耗的无线直连通信，无需路由器中继，确保了语音指令的即时响应。

本项目的核心创新包括：业界首创的MCP工具驱动物联网架构、基于枚举状态机的Flag-driven设备控制模型、融合姿态检测与语音交互的主动式跌倒检测与报警机制、以及适应老年群体使用习惯的零学习成本交互设计。主机采用老人卡挂牌外形设计，内置0.96寸OLED显示屏用于状态提示，配合TP4056太阳能充电管理模块和6V太阳能充电板，实现绿色能源全天候供给，真正成为老年人身边的智能伴侣。

**关键词：** 智慧养老；大模型；ESP-NOW；MCP工具协议；语音交互；分布式物联网；边缘AI

## 第一章 项目背景与研究意义

### 1.1 项目背景

#### 1.1.1 老龄化社会现状

根据国家统计局数据显示，截至2024年底，我国60岁及以上人口已超过3亿，占总人口比例超过21%，其中65岁及以上人口超过2亿，正式进入深度老龄化社会。这一庞大的老年群体面临着诸多生活挑战：身体机能下降导致的意外伤害风险增加、慢性病管理需求突出、独居老人缺乏及时照护等问题日益凸显。

与此同时，许多老年人由于年龄、教育背景等因素，难以熟练使用智能手机等现代科技产品，无法享受到智能科技带来的便利，形成了明显的"数字鸿沟"现象。据统计，65岁以上老年人智能手机APP使用率不足15%，智能家居设备配置成功率不到30%。

#### 1.1.2 老年群体的三大核心困境

**视力退化困境：** 老年人的视力平均每年下降2-3%，智能手机、手表等设备的复杂界面成为难以跨越的使用障碍。老年人需要的是简单、直观、无需盯着屏幕看的交互方式。

**孤独感困境：** 空巢老人、独居老人数量激增，长期缺乏情感陪伴导致心理健康问题频发。调查显示，超过40%的独居老人表示"经常感到孤独"，而现有的智能设备无法提供真正有温度的陪伴。

**意外求援困境：** 老年人跌倒发生率高达30%，其中70%发生在居家环境中。由于无法及时求援，跌倒后无人知晓成为独居老人最大的安全隐患之一。

#### 1.1.3 本项目的提出

基于上述背景，本项目提出"银龄智享"——一个基于大模型与ESP-NOW协议的智慧养老物联网平台。该系统以"让不会使用智能手机的老人也能享受AI和物联网的便利"为核心理念，彻底剥离复杂屏幕与外壳，主打"重感知、轻操作"。

本项目创新性地将MCP（Model Context Protocol）工具协议应用于物联网设备控制场景。MCP是一种标准化的工具调用协议，允许AI大模型通过统一的接口调用外部工具和服务。用户使用自然语言发出的指令，AI可以自动解析意图并调用相应的MCP工具执行操作，真正实现"动口不动手"的便捷体验。

### 1.2 项目定位与目标

#### 1.2.1 核心定位

"银龄智享"的核心定位是"无障碍智慧养老平台"，旨在通过技术创新降低老年人使用智能设备的门槛，让科技真正服务于老年群体的日常生活。

**零学习成本：** 用户无需学习任何操作流程，只需用日常语言表达需求，系统自动完成所有操作。

**主动式守护：** 系统不仅被动响应用户指令，还能主动监测用户状态。当检测到老年人发生意外跌倒时，系统会自动触发报警，及时通知周围人员或紧急联系人。

**场景化联动：** 用户一句话即可触发多个设备的联动操作，如"我要睡觉了"自动关闭所有灯光、打开卧室风扇等。

#### 1.2.2 目标用户群体

**独居老人：** 缺乏日常照护，需要系统提供健康监测和紧急求助功能。跌倒检测和自动报警功能可以有效解决独居老人"发生意外无人知晓"的安全隐患。

**行动不便的老人：** 需要便捷的家居控制方式，减少不必要的体力消耗。通过语音控制，老人只需要说一句话就能完成灯光、风扇等设备的控制。

**记忆力衰退的老人：** 需要用药提醒、日程提醒等辅助功能。本项目的智能药盒功能支持药盒列表管理，到时间自动提醒老人服药。

## 第二章 系统架构设计

### 2.1 整体架构概述

#### 2.1.1 "云脑+端反射弧"架构

"银龄智享"系统采用"云脑+端反射弧"的架构设计，将AI能力按需分配到云端和边缘，实现性能与可靠性的最优平衡：

**云端AI"大脑"：** 深度对接火山引擎豆包大模型，完成16000Hz PCM实时语音转写、意图推理与极速TTS语音下发，打通端到端的AI闭环。

**边缘感知"小脑"：** 依托ESP32-S3的强大性能与MPU6050六轴传感器，在完全断网的情况下，依然具备极高可靠性的本地边缘姿态解算与中断触发能力。

**分布式通信"神经"：** 采用ESP-NOW协议构建"一主机多从机"的分布式架构，主机与从机之间实现低延迟（小于10ms）、低功耗的无线直连通信，无需路由器中继。

#### 2.1.2 系统组成

系统由一台主机和四台从机组成，形成完整的智慧养老物联网生态系统：

**主机设备（智能终端）：** 采用ESP32-S3芯片作为主控，搭载小智AI语音助手固件，支持语音唤醒、语音识别、自然语言理解等功能。主机硬件配置包括：麦克风阵列用于语音采集、0.96寸OLED显示屏用于状态提示、MPU6050六轴传感器用于姿态检测、蜂鸣器用于报警提示、以及ESP-NOW通信模块用于与从机通信。主机设备采用老人卡挂牌外形设计，内置3.7V锂电池供电，配合TP4056太阳能充电管理模块和6V太阳能充电板，实现全天候绿色能源供给。

**一楼从机设备：** 控制一楼区域的灯光、风扇、窗帘等设备，配备3个灯光控制通道、3个继电器控制通道、3个舵机控制通道。

**二楼从机设备：** 与一楼类似，控制二楼区域的家居设备。

**三楼从机设备：** 控制三楼区域的家居设备，配置与一楼、二楼相同。

**智能药盒从机设备：** 作为第四个从机设备，负责药盒状态监测和用药提醒。

### 2.2 硬件架构设计

#### 2.2.1 主机硬件设计

主机设备采用ESP32-S3-N8R16芯片，这是一款功能强大的Xtensa双核32位处理器，主频高达240MHz，具备强大的AI运算能力。

#### 2.2.2 从机硬件设计

从机设备同样采用ESP32系列芯片，根据功能不同进行配置：

**灯光控制通道：** 采用GPIO输出控制继电器的方式实现灯光开关控制。每个从机配备3个灯光控制通道。

**继电器控制通道：** 采用3个继电器模块控制风扇等设备的开关。

**舵机控制通道：** 采用PWM信号控制舵机角度，实现窗帘等设备的精确定位。

#### 2.2.3 太阳能充电管理系统

主机设备采用太阳能供电方案，实现绿色能源的自给自足：

**太阳能电池板：** 采用6V/1W单晶硅太阳能电池板，转换效率高达18%，适用于室内弱光环境。

**TP4056充电管理模块：** 支持0.5A恒流恒压充电，具备过充、过放、过流保护。

**3.7V锂电池：** 容量2000mAh，配合太阳能板可实现全天候不间断供电。

**供电策略：** 优先使用太阳能供电，阳光不足时自动切换至锂电池供电，最大限度延长续航时间。

### 2.3 软件架构设计

#### 2.3.1 MCP工具协议架构

本项目创新性地将MCP（Model Context Protocol）工具协议引入物联网领域，实现AI大模型与硬件设备的标准化对接：

**工具定义层：** 定义标准化的设备控制工具接口，包括设备类型、操作类型、参数范围等元数据。

**协议解析层：** 大模型输出的工具调用请求经过协议解析，转换为可执行的设备控制指令。

**硬件执行层：** 通过Flag-driven状态机将控制指令下发至具体硬件设备执行。

**状态反馈层：** 硬件执行结果通过状态标志位回传，形成完整的控制闭环。

#### 2.3.2 Flag-driven设备控制模型

采用枚举状态机实现设备控制，核心设计如下：

**设备状态枚举：** 定义设备可能的状态，如SERVO_STATE_0、SERVO_STATE_45、SERVO_STATE_90等。

**控制标志位：** 使用枚举类型定义控制标志，如FLAG_SERVO_UPDATE、FLAG_LED_ON等，确保类型安全。

**状态同步机制：** 主机与从机通过ESP-NOW同步设备状态，确保多端控制一致性。

## 第三章 功能模块设计

### 3.1 智能语音交互模块

#### 3.1.1 模块概述

智能语音交互模块是"银龄智享"系统的核心入口，基于小智AI固件进行深度二次开发而成。该模块实现了从语音唤醒到意图执行的完整流程，为用户提供自然、流畅的语音交互体验。

#### 3.1.2 语音唤醒与识别

语音唤醒功能支持自定义唤醒词，用户说出"小智小智"即可唤醒设备进入监听状态。唤醒后，设备通过麦克风阵列采集用户的语音指令。

自然语言理解是本系统的核心能力之一。通过大模型的语言理解能力，系统能够准确理解用户的自然语言表达。例如，当用户说"小智，有点热，帮我开个风扇"时，系统识别到用户想要打开风扇降低温度。

#### 3.1.3 MCP工具调用

当用户发出语音指令时，AI首先解析用户意图，然后调用相应的MCP工具执行操作：

**Iot_Mcp_Set_GPIO：** GPIO设置工具，用于控制灯光、继电器等设备的开关状态。

**Iot_Mcp_Set_Servo：** 舵机设置工具，用于控制舵机角度。

**回家场景工具：** 当用户说"我回家了"时触发，执行打开玄关灯、客厅灯等操作。

**睡眠场景工具：** 当用户说"我要睡觉了"时触发，执行关闭所有灯光、关闭所有窗帘等操作。

### 3.2 跌倒检测与报警模块

#### 3.2.1 模块概述

跌倒检测与报警模块是"银龄智享"系统的重要安全功能，旨在为独居老人提供实时的安全监护。该模块基于MPU6050六轴传感器实现。

#### 3.2.2 跌倒检测算法

跌倒检测算法采用多阶段判断策略：

**第一阶段：冲击检测** —— 实时监测加速度数据的幅值变化，当检测到加速度幅值突然增大并超过预设阈值（如3g）时，认为可能发生了跌倒事件。

**第二阶段：姿态变化检测** —— 分析冲击后的姿态角度变化。如果检测到姿态从近似直立快速变为近似水平，且持续时间超过一定阈值，则进入第三阶段判断。

**第三阶段：静止检测** —— 如果检测到人体在水平姿态下静止超过一定时间（如5秒），则判定为跌倒事件。

#### 3.2.3 报警触发与恢复

一旦判定为跌倒事件，系统立即执行以下报警操作：触发蜂鸣器报警、OLED显示求助信息、语音询问老人状况。如老人在一定时间（如30秒）内自行站起，系统会自动检测到姿态恢复正常，并停止报警。

### 3.3 智能家居控制模块

#### 3.3.1 单设备控制

通过语音指令，用户可以独立控制各个设备：

**灯光控制：** "打开卧室灯"、"关闭客厅灯"

**风扇控制：** "打开风扇"、"把风扇调大"

**窗帘控制：** "打开窗帘"、"关闭窗帘"

#### 3.3.2 场景联动控制

系统创新性地设计了场景化联动功能，用户只需说出一个意图语句，系统即可自动执行一系列预设操作：

**回家场景：** 用户说"小智，我回家了"，系统自动打开玄关灯、客厅灯、客厅风扇等。

**睡眠场景：** 用户说"小智，我要睡觉了"，系统自动关闭所有楼层的灯光、关闭所有窗帘、打开卧室风扇等。

**起床场景：** 用户说"小智，早上好"，系统自动打开卧室灯、打开窗帘、播报天气等。

### 3.4 主从机心跳监测模块

心跳机制的工作原理是：每个从机设备每隔30秒向主机发送一个心跳数据包。主机接收到心跳包后更新该从机的在线状态。当主机连续三个心跳周期（90秒）未收到某个从机的心跳包，则判定该从机离线。

从机在启动时会广播DISCOVER命令寻找主机设备。当从机与主机断开连接后，从机会自动尝试重新连接主机，无需人工干预。

## 第四章 技术实现方案

### 4.1 MCP工具开发

#### 4.1.1 MCP协议概述

MCP（Model Context Protocol）是一种标准化的工具调用协议，允许AI大模型通过统一的接口调用外部工具和服务。MCP协议的核心思想是"工具即服务"，每个工具都有明确的输入参数和输出格式定义。

#### 4.1.2 核心MCP工具

**Iot_Mcp_Init：** 物联网系统初始化工具，初始化ESP-NOW通信模块和设备管理模块。

**Iot_Mcp_Set_GPIO：** GPIO设置工具，用于控制灯光、继电器等设备的开关状态。

**Iot_Mcp_Get_GPIO：** GPIO查询工具，用于查询某个设备或GPIO的当前状态。

**Iot_Mcp_Set_Servo：** 舵机设置工具，用于控制舵机角度。

**Iot_Mcp_Get_Status_JSON：** 状态查询工具，以JSON格式返回所有设备的状态信息。

### 4.2 ESP-NOW通信实现

#### 4.2.1 通信特点

ESP-NOW是乐鑫公司开发的一种快速连接通信协议，具有无需握手、低延迟、低功耗、无需路由器的特点。相比传统的WiFi或蓝牙通信，ESP-NOW更适合家庭环境下的设备互联。

**传输延迟：** 小于10ms

**最大载荷：** 250字节

**通信模式：** 点对点、点对多点

#### 4.2.2 心跳维持与重连

从机每30秒发送一次心跳包给主机。主机收到心跳后回复RESPONSE，更新从机的在线状态。如果从机发送心跳后未收到响应，会尝试重新添加主机为对等节点，然后重试发送。

### 4.3 全局状态管理机制

#### 4.3.1 枚举状态架构

系统中的每个从机设备都维护一组全局枚举值变量，用于存储设备状态信息：

```c
typedef enum {
    LIGHT_OFF = 0,
    LIGHT_ON = 1
} light_state_enum_t;

typedef enum {
    SERVO_0   = 0,
    SERVO_45  = 1,
    SERVO_90  = 2,
    SERVO_135 = 3,
    SERVO_180 = 4
} servo_angle_enum_t;
```

#### 4.3.2 枚举优势分析

**可读性强：** LIGHT_ON比1更直观。

**易扩展：** 如果需要增加新的状态，只需要在枚举中添加一项。

**安全性高：** 编译器会检查类型匹配，避免将错误的值赋给变量。

## 第五章 项目特色与创新

### 5.1 技术创新

**业界首创的MCP工具驱动物联网架构：** 用户可以直接通过自然语言控制设备，AI自动解析意图并调用相应的工具执行操作，大大简化了控制流程。

**基于枚举状态机的Flag-driven设备控制模型：** 确保了状态与操作的一致性，避免了状态不同步的问题。

**融合姿态检测与语音交互的主动式健康守护机制：** 系统集成MPU6050六轴传感器进行跌倒检测，当检测到老人跌倒时自动触发报警。

**ESP-NOW多从机分布式通信架构：** 相比传统的WiFi或ZigBee等通信协议，ESP-NOW具有无需路由器、配对简单、延迟极低的优势。

### 5.2 应用创新

**语音优先的交互设计：** 用户只需通过自然语言即可完成所有操作，无需学习复杂的操作流程。

**场景化的联动控制：** 用户通过一句话触发多个设备的联动控制，如"我要睡觉了"自动关闭所有灯光、打开风扇等。

**适应老年人生理特点的设计：** 在语音反馈音量、提示间隔、提醒方式等方面都进行了专门优化。

## 第六章 社会价值与市场前景

### 6.1 科技向善

科技的终极意义在于不让任何人掉队。本项目用极低的硬件成本和极简的工程美学，撬动了庞大的云端算力，让每一位老年人都能平等地享受AI时代的便利与尊严。

**成本优势：** 整套系统硬件成本控制在200元以内，相比市面上数千元的老年智能设备，大幅降低智慧养老的入门门槛。

**易用性设计：** 无需配置、无需学习、开机即用，真正实现"零门槛"使用体验。

**全天候守护：** 太阳能供电解决了老年人忘记充电的痛点，确保设备24小时在线，守护不间断。

### 6.2 市场前景

中国养老产业市场规模已突破4万亿元，智慧养老赛道正处于爆发前夜。本项目凭借极致性价比和极简交互体验，可迅速推向：

**居家养老：** 为主流独居老人家庭提供安全、便捷的智能养老解决方案。

**社区关怀：** 为社区养老服务中心提供数字化管理工具，提升服务效率。

**养老机构：** 为中高端养老机构提供差异化竞争卖点，打造智慧养老标杆。

### 6.3 伦理与隐私

本项目在设计时充分考虑老年用户的隐私权益：

**本地处理优先：** 姿态检测、语音识别等敏感操作优先本地执行，减少数据上传。

**隐私告知透明：** 设备状态通过OLED屏幕、灯光、声音等直观方式反馈，老人清楚知道设备正在做什么。

**数据最小化：** 仅收集必要的健康数据，不进行商业化变现，保护老人隐私。

## 第七章 未来演进

### 7.1 全屋智能生态联动

胸牌未来可无缝联动全屋智能生态：

**智能药盒联动：** AI可记忆每个药盒的药品信息和用药时间，到时间自动提醒老人服药。

**智能灯光联动：** 当老人夜间起夜时，胸牌感知到体位变化，自动点亮床头灯和西庭灯。

**智能温控联动：** 根据老人体温和室内温度，自动调节空调或风扇风速。

### 7.2 社区养老网络

单个家庭养老向社区养老网络演进：

**邻居互助网络：** 同一社区的老年用户可组成互助网络，跌倒等紧急事件可同时通知邻居和家属。

**社区关怀中心：** 胸牌状态数据可接入社区养老平台，志愿者和社区工作人员可实时了解老人状况。

### 7.3 4G Cat.1升级方案

系统预留4G Cat.1模块升级空间，在没有WiFi的环境下可通过移动网络保持连接，极大扩展产品的适用范围。
